## 1. Context

Phase P1 made the GDELT ingestion trustworthy: a ledger, three quality gates and 30 real days in four silver tables. Two parts of the platform are still missing. The second source, SEC EDGAR, is not ingested, so no table knows a company. And every schedule of phase P1 ran on a laptop, which slept four times during the live run.

Week 3 (phase P2) builds three parts:

1. **A fair-access SEC client.** The SEC allows each user 10 requests in each second and asks every automated client for a declared user agent (finding F1). The client of the platform sends at most 8 requests in any second, lets one process call the SEC at a time, and remembers a block by the SEC in PostgreSQL, so every later task respects the block. The pattern "stop calling after a refusal, and try again later" is named a *circuit breaker*.
2. **Three SEC pipelines and the first business models.** The pipelines load the company reference data, the filing index and the financial facts. dbt builds five models from the data. The company dimension keeps the history of a company (a *type 2* dimension: one row for each period in which the attributes of a company stayed the same). The financial facts carry two times (a *bitemporal* fact: the period which a number describes, and the moment at which the number became known).
3. **The first deployment.** One Amazon EC2 host runs the same Compose stack as the laptop, on Amazon S3 and the AWS Glue Data Catalog in place of the local lake. Terraform creates the network, the roles, the host and the monitoring. No port of the host is open to the internet: the only way to the host is AWS Systems Manager Session Manager, a service which opens a shell or a port forward through an agent on the host.

Four terms appear in every section. A *CIK* (Central Index Key) is the number which the SEC gives each filer. An *accession number* is the identifier of one filing. *XBRL* is the tagged data format of the financial statements, and one tagged number is a *fact*. The *universe* is every CIK with a ticker in the ticker file of the SEC (7,988 on 2026-11-28); the *watchlist* is the 50 companies which receive filing detail and financial facts (BP §4.6).

**Intended outcome:**

- The three SEC pipelines run by schedule on the AWS host, and the request log of the host shows no second with more than 8 requests.
- `dim_company` shows the change of name from "Facebook Inc" to "Meta Platforms, Inc.", taken from the former-name data of the SEC.
- The financial facts of the 50 watchlist companies answer the question "what was known on a given date", and unit tests hold the logic.
- The three GDELT jobs of phase P1 run on the host on S3 and Glue for at least 6 unbroken hours, the daily run at 08:25 UTC included.
- The host has no inbound rule, no SSH key and no long-lived AWS key.
- A workflow deploys a commit of `main` after one approval by Jay; `make demo` and the four workflows of phase P1 stay green.

### WP-03 — Fair-access client (4 h)

**Goal.** Every request to the SEC goes through one client. The client cannot exceed the ceiling, cannot hide the identity and cannot ignore a block (BP §4.3, FR-07).

**Produces.** `src/gbmi/sources/sec/` with `urls.py`, `errors.py`, `limiter.py`, `circuit.py` and `client.py`; three settings; `tests/ledger/sec_server.py`; the Makefile target `redact-check` of §3.3; tests.

1. **`limiter.py`, pure code.** `SlidingWindowLimiter(max_requests, window, clock, sleep)` with `acquire()`, which returns the seconds waited. The first call waits one window after the client has received the advisory lock. Property tests with a controlled clock: for any series of arrival times, no window of one second holds more than 8 grants; the grants keep the order; no grant waits longer than the rule asks.
2. **`circuit.py`.** One pure function classifies an answer from status, host, path and the first bytes of the body: `ok`, `missing`, `blocked`, `retry` or `error`, with one test for each row of the table (200; 404 on `data.sec.gov`; 403 with the XML body of F9; 403 with another body; 429 with and without `Retry-After`; 500; 503). The class `Circuit` applies the rules of §3.3 on `ops.source_circuit` with a clock and a sleep function as arguments.
3. **`client.py`.** `SecClient` is a context manager. At the start the client takes the advisory lock and checks the source setting and the user agent (§3.3). `get` and `head` return the body, the status and the time of `Last-Modified`; `download` streams a large file to a path with bounded memory and counts as one request. The client follows no redirect. Each attempt runs in the same order: read the circuit, wait in the limiter, write the log row, send with the headers of F1, add the outcome to the log row, classify, act. Time limits: 10 seconds to connect, 60 seconds for a read, 30 minutes for the archive **[E]**.
4. **Settings.** `GBMI_SEC_MAX_RPS` (1 to 8), `GBMI_SEC_SOURCE` (`fixture`, `live` or `off`) and `GBMI_SEC_FIXTURES_DIR`; `sec_user_agent` becomes a secret type. `.env.example` gains `GBMI_SEC_USER_AGENT=` without a value and with a comment. `compose/compose.yaml` passes the two variables to the Airflow services and to the toolbox, and the Makefile sets the source for each stack: `fixture` for the demo stack, `live` for the working stack until the first deployment. The log format stops rendering local variables in a traceback (F19, l).
5. **The fake SEC server** follows `tests/ledger/gdelt_server.py`: prepared answers for each path, and a list of every request with the time of arrival.
6. **Tests.** Every request carries the three headers. The value of the user agent stands in no captured log line and in no row of `ops.source_request`. A live client refuses to start without a value, without `@` and with the placeholder; a client with the source `fixture` or `off` builds no network transport. An exception which is raised inside the sending code and logged holds no value, in the log line and in the error text of `ops.pipeline_run`. A 429 opens the circuit, the client waits by the controlled clock, sends one probe and closes the circuit; a second 429 in the same run raises `SourceBlockedError`; a refused probe locks the circuit until the operator command. A 403 with the body of F9 raises `ObjectMissingError` and opens nothing; three such answers in a row for listed objects open the circuit. A status of 500 is tried at most 5 times, and each attempt passes the limiter. A second client waits for the lock of the first client: the first client sends 8 requests, the second client follows at once, and the arrival list of the server holds no window above 8. A killed run leaves the rows of every request which left. One test uses the real clock: 24 requests against the mock transport, and no window of one second in the arrival list of the server holds more than 8.

**Done when.** The tests pass, mypy passes in strict mode for `gbmi.sources.sec`, and the coverage of the package is at least 80%.

## 10. Risks, time boxes and cut order

| Risk | Signal | Response |
|---|---|---|
| The SEC blocks the address (risk R13 of the blueprint) | A 429 or a blocking 403; an open circuit in `ops.source_circuit` | The client stops by design. Nobody works around a block. The runbook of WP-09 applies, and Jay is told in the same hour. The cause is found from the request log before the next live run |
| A file of a company outside the three samples breaks a model | Documents in quarantine; unknown-field counts above zero | The model follows the file. A document in quarantine holds back one company only |
| The archive of 1.58 GB arrives slowly or breaks | No complete file after 30 minutes | The fallback of WP-06: the ticker file for every company, full attributes for the watchlist; the next Sunday tries again |
| ClickHouse refuses the role form of the pin (F13) | The smoke test of WP-12 fails at the pinned read | `GBMI_CH_LAKE_ACCESS=keys`: the form which spike SK2 proved |
| Compose does not apply `!override` and `!reset` as the documentation says | The overlay test of WP-10 fails | Three Compose files (§3.3) |
| No spot capacity, or a spot price near the on-demand price | An apply error for the instance; the price history | `host_market = "on_demand"` for the week |
| The host is too small (risk R4) | A memory kill in a control group; swap in steady use; a charge for surplus credits | Metabase stays off; the triggerer stops until phase P5 needs the triggerer; ClickHouse gets a lower limit. The fallback of the blueprint is a `t4g.xlarge` on a shorter schedule (BP §9.1): a cost decision for Jay, with the numbers of WP-13 |
| The sign-in of Jay ends during an apply | "Your session has expired. Please reauthenticate using 'aws login'." | A new sign-in (J3); `terraform plan` again before any further apply |
| A policy check rejects the Terraform code | checkov or tflint fails | Repair the code. A skip is allowed only for one of the reasons of WP-11, step 3, written in `.checkov.yaml` |
| A secret reaches the repository, an image, the site or the state | gitleaks; the search of the site files; the search of the state | Rotate the entry by the runbook of WP-12; remove the artefact; record the event (risk R23) |
| The host does not start at 08:00 UTC: no spot capacity, or the scheduler cannot start a stopped spot instance (§3.3) | `make host-status` shows a stopped instance after 08:05 UTC | Start the instance by command. When the start fails for capacity: `host_market = "on_demand"` and an apply (J4). The ledger catches up after any stop |
| The image cannot become public | Action J6 fails | The host builds the image from the commit, about 15 minutes for each deployment **[E]** |
| The workflow `e2e` becomes slow | Above 20 minutes | The drills run only on pushes to `main`; the DAG tests stay on every pull request |
| The concepts of a watchlist company fit no row of the metric seed (risk R15) | The coverage of a metric is low | The report states the coverage of each metric. No concept is guessed |
| The week runs long (risk R27) | More than 31 hours used before WP-10 starts (28 are planned) | Apply the cut order |
